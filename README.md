# 🌿 AI-Powered Plant Disease Classification

A convolutional neural network that classifies plant leaf images into 38 disease
(or healthy) categories across 14 plant species, served through a Streamlit web app.

## How it works

The project has two parts:

1. **`train.py`** — trains the CNN on the [Plant Disease dataset](https://www.kaggle.com/datasets/saroz014/plant-disease)
   from Kaggle and saves the trained weights.
2. **`app.py`** — loads those trained weights and serves a web interface where you
   can upload a leaf photo and get a disease prediction, or upload a labeled test
   set to evaluate the model's accuracy.

The model never trains inside `app.py` — it only rebuilds the same network
structure and loads the already-learned weights into it, which is why running
the app is fast (a few seconds) rather than slow (training takes much longer).

## Dataset

- **Source:** [saroz014/plant-disease on Kaggle](https://www.kaggle.com/datasets/saroz014/plant-disease)
- **Structure:** already split into `train/` and `test/` folders, each containing
  38 subfolders (one per class) named like `Apple___Apple_scab`, `Tomato___healthy`, etc.
- **Labels:** derived automatically from these folder names — nothing is labeled by hand.

## Model architecture

A CNN with 4 convolutional blocks, increasing in filter count, followed by a
dense classification head:

```
Input (128×128×3)
→ [Conv2D(32) → BatchNorm → MaxPool] 
→ [Conv2D(64) → BatchNorm → MaxPool]
→ [Conv2D(128) → BatchNorm → MaxPool]
→ [Conv2D(256) → BatchNorm → MaxPool]
→ Flatten → Dense(256) → Dropout(0.5) → Dense(38, softmax)
```

Trained with the Adam optimizer and data augmentation (rotation, shifts, zoom,
horizontal flip, brightness variation) applied only to the training set.

**Important:** `build_model()` in `train.py` and `app.py` must stay
identical — `app.py` rebuilds this exact structure so the saved weights load
into the correct slots. If you change the architecture in one file, update the
other to match.

## Setup

### 1. Install dependencies

```bash
pip install tensorflow streamlit pillow numpy pandas scikit-learn kagglehub
```

### 2. Train the model

Run `train.py` in an environment with GPU access (Google Colab recommended).
It will:
- Download the dataset from Kaggle via `kagglehub`
- Train the CNN with data augmentation
- Save the trained weights to `model.weights.h5`
- Save the class label mapping to `labels.json`

> **Naming matters:** the weights file must end in `.weights.h5` (not just
> `.h5`) — Keras chooses how to read the file based on that exact suffix, and
> the wrong suffix will fail to load even though the file itself is valid.

### 3. Run the app

Place `model.weights.h5` and `labels.json` in the same folder as `app.py`, then:

```bash
streamlit run app.py
```

Open the local URL Streamlit prints (usually `http://localhost:8501`).

## Using the app

**Predict tab** — upload a single leaf photo (`.jpg`/`.jpeg`/`.png`) and get:
- The predicted disease (or "healthy") class
- A confidence percentage
- An expandable breakdown of probabilities across all 38 classes

**Evaluate tab** — upload a `.zip` of labeled test images (one folder per class,
matching the training class names) to get:
- Overall accuracy, precision, recall, F1 score, and cross-entropy loss
- A per-class precision/recall/F1 breakdown
- A confusion matrix showing which classes get mixed up with each other

## Project structure

```
.
├── train.py            # Training script — run once to produce the model
├── app.py               # Streamlit app — Predict + Evaluate tabs
├── model.weights.h5     # Trained weights (generated by train.py)
├── labels.json          # Class index → class name mapping (generated by train.py)
└── README.md
```

## Notes

- Precision, recall, and F1 use **weighted averaging** across classes, which
  accounts for class imbalance (some disease classes have far more training
  images than others).
- The Evaluate tab expects images grouped in folders named exactly like the
  training classes (e.g. `Apple___Apple_scab`); folders with unrecognized
  names are skipped and reported, not treated as errors.
